# 独立レビュー（Agent C）

調査実行日: 2026-11-03。実装進行中のスナップショットに対する指摘であり、最終ゲートの成否は `execution-report.md` と検証コマンドで確認する。

## ブラウザ調査結果

- Headless Chromium を実際に起動し、オーナー完全一致・全件・該当なし検索、一覧ページ送り、登録/編集フォーム、入力エラー、Pet/Visitフォーム、獣医師一覧、500/404画面、モバイルナビを確認した。
- `discovery-browser.json` に31操作・19画面状態を保存した。19状態には同一画面の正常/エラー/モバイル表示を含むため、独立したページ数とは異なる。
- Controller/Template側にのみ存在する登録成功、更新成功、境界ページ番号、サイズ超過、未来誕生日、重複ペット、日付制約、欠損IDは、生成されたE2Eテストで追加実行する必要がある。ブラウザ調査だけではこれらを完了としない。
- ブラウザ固有の確認事項はナビの展開/折り畳み、アイコンのアクセシブル名、日付入力のブラウザ制約、実際のスクリプト例外である。

## 実証した環境/Locator上の問題

1. Chromium初回起動は `libglib-2.0.so.0` 不足で失敗した。`npx playwright install-deps chromium` を実行し、依存導入後に再実行成功。Dev Container再構築なし。
2. モバイルの `.navbar-toggler` にアクセシブル名がない。POMで `button.navbar-toggler` を使い、テストからCSSを排除する。
3. 共通ナビにはアイコンのテキストが含まれるため、`getByRole('link', {name:'Home', exact:true})` 等が一致しない。`title` を用いるPOM Locatorで解決する。
4. ページ送りはアイコンリンクで、安定した識別は `a[title='Next']` 等である。番号リンクはroleと正確な番号を使える。
5. 並列ブラウザ実行中に空きメモリ126MBとなりrendererがクラッシュした。ブラウザ調査とE2E実行は逐次化し、失敗時はブラウザを確実にcloseする。証跡欠損を合格にしない。

## アプリケーション既存不具合

`/owners/1` を開き `pageerror` イベントを待って、`Cannot read properties of null (reading 'style')` を実測した。`ownerDetails.html` の `hideMessages` は存在しない `success-message` / `error-message` を参照する。アプリ本体は変更していない。表示メッセージが消えることとJavaScriptエラーが発生しないことは別々の基準である。実行報告に既存不具合を明示し、コンソールエラー不在を検証したとは報告しない。

## 共通基盤への指摘（メインAgentに通知済み）

- 全ての個別 `expect` をReporterで保存するだけでなく、`expect-results.json` の存在・ID・成否・action対応も実行時検証に含める。Evidence.assertのグループ結果だけで全アサーションの完全性を保証しない。
- リトライを別ディレクトリに保持し、成功した最終試行と先行失敗を区別する。実行報告でflakyを隠さない。
- アサーション失敗時は `assertion-end` に加えエラーのイベント記録も保持する。
- AST解析は直接呼出しに加え、分割代入・関数別名・計算プロパティなどの迂回例を不正データテストで確認する。解析は任意のTypeScriptの意味解析を完全に証明するものではない。
- ソースのみ/ブラウザのみで発見された操作を対応づけるとき、同じページという理由だけで無関係な試験にsourceRefを付けない。対応アクションのoperationとexpectedを照合する。

`reconciliation.json` に72件のTemplate/Browser操作の手動対応を保存した。44件はレビュー時点のdraftで未参照だった。POM呼出しとexpectを照合し、存在する操作IDを検査した。ブラウザで観測した編集画面の英字電話番号（BRW-005）は新規画面の同じバリデーションと混同せず、編集側の明示的な追加試験が必要な未対応として残した。

common draft E2E-050-06のMVC-044は獣医師JSON APIを指し、意図した例外画面MVC-043への修正が必要。Visit登録04009は説明の表示を検証するが、表示日付の一致は独立にassertしていないため、日付一致検証済みと説明しない。

Agent定義4種とSkillは編集範囲の分離、逐次ブラウザ、仕様正本、POM、証跡、機械的ゲート、過去の実測失敗を適切に反映している。既存AGENTS.mdのガイドラインも維持されている。除外理由はJSON API/通常UIでは到達しない偽造リクエスト/競合DB例外/存在しない削除操作に限定されており、HTML UIの失敗を隠す除外は見当たらなかった。未知の操作不存在は保証しない旨も明示されている。

追加レビューでE2E-056の編集時英字電話番号の拒否と元データ維持を確認し、BRW-005の未対応を解消した。MVCのPet/Visitルート・入力制約・重複判定・更新時の自己名許容・任意の空日付を実際の試験操作へ追加照合した。`reconciliation.json` の既存draft参照との和集合では対象操作の未対応は0件。これは実装の対応関係であり、実行合格・証跡完全性は最終runの検証結果で別途判定する。
