Validation entry points are package.json scripts. contracts.ts checks schema, discoveries and model references; ast.ts analyzes actual TypeScript syntax and resolved POM calls; runtime.ts reconciles reporter results with evidence and decodes PNG files. report.ts generates the coverage matrix and execution report from the latest completed run. The canonical test design is docs/e2e/specification.yaml; generate its Markdown with npm run e2e:generate-docs.

Run npm run e2e:test-validators before trusting validator changes. Fixtures in negative tests include missing IDs, duplicate IDs, unknown references, POM bypasses, missing/corrupt screenshots, wrong identities, failed assertions, bad event ordering and Markdown drift. Arbitrary TypeScript behavior and screenshot semantics cannot be proven by these checks.
